# 技术决策记录（只追加，不改历史）

> 规则：每次定下一个"会影响多人"的技术决定，就在这里加一行块。
> 目的：防止"定了又推翻"，也防止新人问"为什么当初这么定"。
> 追加格式固定：日期 / 决定 / 理由 / 影响谁 / 何时复核。

---

## 2026-11-02 · 后端用 FastAPI

- **决定**：后端统一 FastAPI + Pydantic，不用 Flask/Django。
- **理由**：自动生成 `/docs` 交互文档，零基础同学也能照示例调接口；契约即代码，与 `app/schemas` 一致。
- **影响**：负责人 A/B/C 都要写 APIRouter；智能体提示词里指定 FastAPI 写法。
- **复核**：若第 3 周出现"路由注册冲突"，再考虑拆服务。

## 2026-11-02 · 模块之间只传 Evidence / Decision

- **决定**：禁止直接 import 其他模块内部实现，交接只用 `app/schemas` 的模型。
- **理由**：五个人并行开发，没有统一交接物必然对不上；也让契约成为唯一需要 review 的地方。
- **影响**：所有人；改契约需队长公告。
- **复核**：第 5 周联调时若发现字段不足，集中加一次。

## 2026-11-02 · 代码审查降级为"三条命令"

- **决定**：不做人工代码评审，改为 `lint / test / smoke` 三条命令 + PR 贴输出。
- **理由**：队员看不懂代码，人工评审会退化成"队长读全部代码"，八周内不可执行。
- **影响**：所有人；PR 没贴输出不合并。
- **复核**：若出现"命令全绿但演示跑不通"，需要补一条端到端用例。
