# ADR-0005 · 前端未定时，验收看"命令 + 输出"，不看页面

- **状态**：生效（2026-11-08）
- **一句话**：前端没定稿之前，"能不能在页面上点出来"不是验收判据；判据是**一条别人能复现的命令 + 真实输出**。

## 背景

前端（T-04，D 负责）还在改，D 的页面每天变。这带来三个具体问题：

1. 后端交付（T-06 模型证据、T-13 媒体预处理）没有稳定出口可看效果，只能等页面；
2. "等页面"实际上等于"等一个还没被定义的东西"，交付卡在验收这一步；
3. 页面一旦变化，昨天"验收通过"的结论今天就不可信了。

同时仓库有硬约束：`main` 只认 PR、四条命令必须全绿。所以"看到效果"必须有一条不依赖页面的通道。

## 决定

1. **验收判据改为"命令 + 输出"**：负责人本地把分支合进临时分支 `try/<任务号>-<日期>`（从 `origin/main` 拉），
   跑一遍，把**命令原文和真实输出**贴进 PR。页面截图算加分，不算判据。
2. **四条命令是底线，不是证据**：它们只证明"没倒退"，不证明"新东西真的工作了"。
3. **临时分支不进远端、看完就删**：`try/` 分支不 push；本地 `main` 始终保持与 `origin/main` 一致，
   否则下一次 `pull` 必冲突（这也是不直接改本地 main 的原因）。
4. **写进三处**：`AGENTS.md` §3 第 12 条（DoD 六条）、`docs/tickets/_模板.md` §6 新增子段、
   三张在用任务单（T-04 / T-06 / T-13）各补一段"没有前端时怎么看效果"。

## 代价

- 每个负责人多一步"合临时分支"的操作，约 2 分钟；
- 有些效果（动画、布局）确实只能靠页面，这类验收仍然需要截图，只是不作为唯一判据；
- 临时分支有被误 push 的风险，靠"不 push + 看完即删"的纪律约束，门禁无法自动检查。

## 什么情况才推翻

前端定稿并且稳定两周（T-04 的 `status: final` 且连续两个 PR 没改页面结构）之后，
可以把"贴命令与输出"降级为"贴页面截图"，但**必须保留可复现的一段命令**，否则以后无法复测。
