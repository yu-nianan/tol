# ADR-0008 前端与原型一致性：原样搬入 + 适配层唯一改造点

## 状态

已采纳（2026-11-25）。

## 一句话

前端**就是原型**：`index.html` / `style.css` / `profile.js` / `alert.js` / `report.js` 原样搬入，
只在 `app.js` 里把"本地假判别"换成调后端；所有数据形状差异由新增的 `frontend/adapter.js` 抹平。

## 背景

上一版（PR #20）为了"功能对齐"重写了 HTML 结构与 CSS，交互与观感都和原型不一样，
用户明确要求"交互和样式要和原型完全一样"。原型本身零依赖、无构建，天然满足技术栈约束（ADR-0001）。

## 决定

1. **原型文件原样进仓**，唯一改动是资源路径（`style.css` → `/static/style.css`，脚本按
   `adapter → profile → alert → report → app` 顺序引用），渲染函数与 CSS 一个字不改。
2. **新增 `frontend/adapter.js` 作为唯一改造点**：它产出原型 `analyze()` 需要的形状
   `{score, level, stage, stageIdx, stageW, flags, bias, ev[], themCount, themMsgs, meMsgs, turns,
   scriptName, key, dims}`，内部调 `POST /api/v1/detect/text`（只送新增的对方轮次；换角色或对话变短时换 session 重放）。
3. **后端多透一个 `dim_weights`**（百分数），前端不写权重常量；维度贡献 = 得分率 × 权重。
   这是对 ADR-0006 的补充：`dims` 是 0–1 得分率，`dim_weights` 是权重，二者都只由 `scoring.py` 定义。
4. **阶段槽位映射写死在后端语义上**：`stage_contact→0 / stage_authority→1 / stage_isolation→2 /
   stage_transfer→4`（原型第 3 格"诱导操作"没有后端对应，永不点亮，已记入 T-15 已知限制）。
5. 页面不再有任何编造的数据：会话号来自 adapter，时延来自 `latency_ms`，知识库版本号显示"未登记"，
   通知记录优先用 `/api/v1/report/{sid}` 的 `notifications`。

## 代价

- 前端多一层适配代码（约 240 行），后端契约每加/改一个字段都要动这一层。
- 阶段条第 3 格永远是灰的；后端剧本若改阶段中文名，前端仍显示原型词汇（`STAGES`）。
- 告警列表、逐轮曲线仍由前端累积（后端无列表接口、report 无逐轮历史），刷新即丢，已在 T-15 §6 记录。

## 什么情况才推翻

后端提供告警列表接口与逐轮历史后（那时可以去掉前端累积）；或原型改版、需要换视觉基线时。
推翻前先读本页与 T-15，再按 `docs/agents/进度与决策记录.md` 写新 ADR。
