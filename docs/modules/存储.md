# 运行时库

## 一句话职责

**吃** `SessionState` / `Alert` / 单条消息，**吐**重启后仍能读回的会话、消息流水与告警状态。超出这句的都算越界。

## 输入 / 输出

| 方向 | 类型 | 从哪里来 / 到哪里去 |
| --- | --- | --- |
| 入 | `SessionState`（引擎内部结构） | `decision/engine.py` 每次判别后写 |
| 入 | `Alert` | `engine._open_alert()` 产生时写 |
| 出 | `SessionRecord` / `list[MessageRow]` / `Alert` | 回给 `engine`（重启后 hydrate）与 `/api/v1/stats` |

## 关键实现与取舍

- **SQLite 文件即数据库，不引入服务与 ORM**：任务书只要求"可运行程序"，多一个数据库服务就多一处演示失败点；代价是并发写靠 `timeout` 兜。
- **`init_db()` 幂等 + `schema_version` 版本号**：启动时 `CREATE TABLE IF NOT EXISTS`，跑十次结果一样；以后加字段靠版本号判断，不靠猜。
- **复杂字段存 JSON 字符串**（`evidence` / `notifications` / `last_decision`）：表结构稳定，改 Pydantic 模型不用改表；代价是没法用 SQL 直接查数组内部。
- **内存 dict 只当热缓存**：真相永远在库里，`_hydrate()` 在缓存缺失时回读；`RESET_DB=1` 才清空，平时启动绝不删表。
- **`.db` 不进 git**：`.gitignore` 已忽略 `data/*`，谁拉下来第一次运行自动生成。

## 边界：不做什么

- 不做画像、冷却、白名单（那是 T-09 / FR-2.6 的活）——这里只存"发生了什么"。
- 不存案例库与剧本库（那两份是人写的 JSON，走 `app/kb/`）。
- 不做向量化与检索（入库流水线的索引部分归 A）。

## 怎么测

- 单测位置：`tests/storage/`
- 一行可复制的命令：`python -m pytest tests/storage -q`

## 常见坑

- `sqlite3.connect()` 默认同一线程只能用一个连接；跨线程要 `check_same_thread=False`，本模块每次开新连接所以不碰这个坑。
- `data/` 被 `.gitignore` 忽略，测试必须用 `tmp_path`，别往 `data/app.db` 里写测试数据。
- 时间统一存 ISO 字符串（`created_at.isoformat()`），不要存 `datetime` 对象——SQLite 会悄悄转成 float。

## 改动须知

表结构（`SCHEMA`）改动 = 契约级改动：先升 `SCHEMA_VERSION`，再在 `init_db()` 里写迁移分支；会影响 `engine` 的 `_hydrate/_persist`，改前先跑 `python -m pytest tests/storage tests/test_api.py -q`。
