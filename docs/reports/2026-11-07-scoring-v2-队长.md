# 任务回执：T-07 打分器 v2（负责人 队长）

## 做了什么

- `app/pipelines/decision/scoring.py`：新增 `STAGE_WEIGHT_STEPS=(0.35,0.6,0.8)`、`STAGE_FLOOR_FROM=3`、
  `STAGE_FLOOR_SCORE=60.0`、`STAGE_MIN_SIM=0.6`、`STAGE_MIN_HITS=2`；`stage_index(script)` 按阶段权重映射 1–4；
  `evaluate(..., stage_floor=0.0)` 增加阶段下限：`score < floor` 时抬到 60 并把理由写进 `reasons`，
  下限在"无证据封顶"之前生效（两者都触发时仍封 60）。
- `app/pipelines/decision/engine.py`：
  - `SessionState.stage_index` 单调不减（正常消息不让阶段回退）；`Decision.stage_index` 取会话最大值。
  - `_match_script(text)` 重写：**按剧本累计命中信号数选剧本**，再取该剧本内走得最远的阶段；
    仅当"命中数 <2 且比例 <0.6"才丢弃。目的：避免 S01 立威里的"涉嫌洗钱"被 S10 转账阶段
    （0.665）抢走而把会话误判成第 4 阶段。
  - 证据累积：`dedupe(历史最近 40 条 + 本轮)`，同一句话重复出现不涨分。
  - 接入 T-06：`settings.llm_enabled` 时调 `llm.extract_evidence`，失败返回空列表不影响规则结果。
  - 接入 T-09：白名单命中且无规则证据 → 直接 L0；`context_evidence` 进证据链；画像偏移只叠加
    "历史告警次数"部分（`offset - bias`，角色 bias 已在 `scoring` 加过，避免重复 +8）；
    告警前过 `should_notify`（30 分钟同级冷却），`record_alert` / `record_ack` 落盘。
  - FR-2.7：`cited_case_ids` 为空时分数封顶 60、`cap_applied=True`。
  - L1 起就调 `notify_guardian`（原先只有 L3），分档由 notify 层做。
- `app/api/detect.py`：文本/音频/图片共用 `_detect()`；`/detect/audio` 用 `transcribe(data, suffix)`，
  空文本回 501 `asr_not_configured`；`/detect/image` 用 `extract_text`，空文本回 501 `ocr_not_configured`；
  `UnsupportedAudioFormat`/`UnsupportedImageFormat` → 415，`ImageTooLarge` → 413，**文本为空时不编造内容**。
- 文档：新增 `docs/modules/decision.md`（职责/输入输出/取舍/边界/测试/常见坑/改动须知）。
- 契约变更（已在 m00152 块公告）：`Decision` +`stage_index`、+`cited_case_ids`；`SourceKind` +`CONTEXT`、+`CROSS_MODAL`。

## 没做完 / 已知问题

- **"准"只在本仓库 20 条自拟黑样本上验证过**：阶段法平均 1.15 轮报警、关键词法 13.00 轮、18/18 提前，
  但样本是我自己按剧本写的，偏理想化；真实通话录音（T-02 转写）上的误报率还没测。
- 阶段法有一处保守：若某剧本只有 2 个信号命中且比例 <0.6，整段对话按"无剧本"处理（封顶 60），
  长对话中"只提了一个阶段"的合理场景会被压低，属于用准确率换召回。
- 关键词法的"99"是测试内部口径（4 轮不出现转账），**不是 API 返回值**，也不对外暴露。
- T-09 的 `context_evidence` 目前只进证据链、不参与加权（`scoring` 只认固定 code），"跨轮上下文影响分数"
  这件事实际是靠历史证据累积 + 画像偏移实现的，语义上没有单独维度。
- 前端（T-04）需要读 `decision.stage_index` 画进度条，D 的页面已按 1–4 做，但真机联调还没跑。

## 下次接手要知道什么

- 入口：`DetectionEngine.detect_text(text, session_id="default", role="normal") -> (SessionState, Decision, Alert|None)`；
  `get_engine()` 是 `lru_cache(maxsize=1)` 单例，测试里要 `get_engine.cache_clear()` 或直接 `DetectionEngine(kb)`。
- 想调"多早报警"就改 `STAGE_FLOOR_FROM` / `STAGE_FLOOR_SCORE`；想调"多难算命中"改 `STAGE_MIN_HITS` /
  `STAGE_MIN_SIM`，两者一起调，否则"只出现一个通用词"会被当成阶段证据。
- `ScriptHit.stage_score` 是 property（= `stage_weight`），`match_script` 会把 `stage_weight` 改写成加权系数，
  **不要**从 `ScriptHit` 反解命中比例；要比例就在 `_match_script` 里自己算。
- 分数构成 = 六维加权（stage/entity/pressure/cross/channel/profile，缺维剔除后归一）×100 + 角色 bias +
  画像额外偏移（−bias），最后可能被阶段下限抬到 60、被无案例封顶压到 60。改任何一项都要同步
  `docs/modules/decision.md` 与 `docs/需求覆盖表.md` 的说明列。
