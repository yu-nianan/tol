# 任务单：媒体预处理（音频 + 图片）

## 1. 背景（为什么做这件事）

对应需求：`FR-1.6`（媒体预处理）。它撑着三件事：音频能进（`FR-1.2`）、图片能进（`FR-1.3`）、跨模态比对有料可用（`FR-2.4b`）。

**先说结论：现在系统只认"理想素材"，真实素材基本进不来。**

- **录音**：只认最标准的 wav。微信里那种语音消息、iPhone 自带录音，**一个都进不来**，会直接被拒。
- **截图**：手机截图动不动就三四兆，**超过上限会被直接拒**；竖着拍或竖着截的图，方向信息没处理，识别出来的文字位置是歪的。
- **留证**：现在没有"原始素材存哪、留多久"的规矩。演示时用真手机号、真录音，很可能最后把它们留在仓库里。

一句话：**这一步不是锦上添花，是"演示时能不能用自己的手机试"的分界线。**

## 2. 目标（做完之后，什么会不一样）

做完之后，队友拿自己的手机随手录一段、截一张图，**能直接扔进来跑**，而不是先去找格式转换工具。具体要求：

1. **音频**：常见录音格式能进就进；进不了的要**明确告诉用户"这个格式不行，请转成什么"**，而不是报一个看不懂的错。
2. **图片**：竖拍/竖截的图方向要正；太大的图**不要直接拒**，要么自动缩小，要么明确提示"太大，请裁一下再传"。
3. **脱敏**：手机号、卡号这类东西，在图片里要能**定位出来并标记**（真正打码可以后面做，但位置要先能算出来）。
4. **留痕**：每次处理都留下"这份素材是什么、动过什么、有没有被截断"的记录；**原始文件不进仓库**。
5. **守住底线**：没有能力处理的时候，**直说"处理不了"，绝不假装处理成功**。

## 3. 输入 / 输出样例（写死，不要"大概"）

**输入是素材，输出是一段"这份素材现在什么样"的说明。**

| 你拿什么试 | 期望看到 |
|---|---|
| 微信里存下来的语音（m4a） | 要么能转成可识别的音频继续走，要么明确提示"这个格式需要先转码"，**不许静默失败** |
| iPhone 录的一段 3 秒通话 | 能读出来、能切出有声音的段落、音量不会忽大忽小 |
| 竖着截的手机屏（聊天界面） | 方向被摆正，后面的文字识别框位置是对的 |
| 一张 5MB 的长截图 | 不会一句"文件太大"就完事，而是给出"需要缩小到多少"或直接缩好 |
| 一张含手机号的聊天截图 | 能标出手机号在画面里的位置（后面才好打码） |
| 一段 5 分钟的录音 | 明确告诉你"只处理前 3 分钟"或"太长，请分段"，不许无声截断 |

## 4. 允许修改的路径（超出即越界）

```
app/pipelines/media/**        # 新增的一段预处理，专门负责"喂给识别之前"
tests/media/**                # 你的测试
data/samples/media/**         # 你自己准备的素材，本地放着即可，不进仓库
```

**不要去改**：识别模块本身（音频转写、图片识别）、接口层、字段定义。你负责的是**"进识别之前那一步"**，不是识别本身。

## 5. 不许做的事（本次特有）

- **不许装新库。** 需要转码、缩放、打码这类"重活"，用队里已有或可以申请的外部工具，别自己引一个包进来。
- **不许假装成功。** 处理不了就是处理不了，说清"缺什么"，不许返回一个看起来正常、其实是空的结果。
- **不许把真实素材留在仓库里。** 演示用的真录音、真截图、真手机号，用完要清掉，只能留"这份素材存在过"的记录。
- **不许在这一步做判断。** 这里是"洗干净"，不是"判断是不是诈骗"——那是后面的事，别越界。
- **不许吞错误。** 出错就报出来，说清是哪类错，别用一句"出错了"糊过去。

## 6. 验收（做到什么算完）

**流程**：照老规矩提 PR，四条命令全绿（lint / 测试 / 冒烟 / 文档检查）。命令不用背，`AGENTS.md` §2 里就写着。

**演示清单**（做完拿这六份素材各试一遍，结果发群里，截图或一行字都行）：

- [ ] 微信语音（m4a）：要么能用，要么给出"怎么转码"的明确提示
- [ ] iPhone 录音：能读出时长、能切段
- [ ] 48k 立体声录音：不炸，结果正常
- [ ] 竖拍截图：方向正、文字位置对
- [ ] 5MB 长截图：有明确的"缩到多少"或直接缩好
- [ ] 含手机号的截图：能标出号码位置

另外一条：**速度要能接受**——图片基本"点一下就出来"，30 秒的录音不要等十秒以上。

### 没有前端时怎么看效果（这段没有接口，别等页面）

预处理是"进识别之前那一步"，前端没定、也还没接口。所以看效果的出口是**一个临时脚本**：

```powershell
git fetch origin
git switch -c try/T-13-<日期> origin/main
git merge <你的分支>
python -c "import json; from app.pipelines.media import prep; print(json.dumps(prep(r'data\samples\media\wx.m4a'), ensure_ascii=False, indent=2))"
```

（`prep` 这个名字以你实际实现为准；脚本放 `data\` 下，**别提交**。）

六份素材各跑一遍，打印出来的东西要能回答四件事：**多长、切了几段、方向转了没有、有没有被截断或缩过**。
把这段命令和真实输出贴进 PR——这就是"我看过效果了"的证据。四条命令全绿只是没倒退，不证明这一步真的工作。

看完清干净：`try/` 分支不 push，看完删掉；本地 main 保持和 `origin/main` 一致。
