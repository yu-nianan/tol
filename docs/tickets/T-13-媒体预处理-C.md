# 任务单：媒体预处理（音频 + 图片）

## 1. 背景（为什么做这件事）

对应需求：`FR-1.6`（媒体预处理），支撑 `FR-1.2`、`FR-1.3`、`FR-2.4b`、`NFR-1`。

现在的两条链路**只认"理想素材"**：

| 现状 | 代码位置 | 真实素材会怎样 |
|---|---|---|
| 音频只吃 **16bit PCM wav**，其它一律 `UnsupportedAudioFormat` | `app/pipelines/audio/asr.py` 的 `_read_wav` | 微信语音（m4a/amr）、iPhone 录音（m4a）**一个都进不来**；48k 立体声能进但没做增益归一，安静段 VAD 切不出段 |
| 图片只吃 PNG/JPEG，`>4MB` 或 `>4000px` 直接拒 | `app/pipelines/vision/ocr.py` 的 `_read_size` / `ImageTooLarge` | 手机截图 3–8MB 常见，**一半会撞门槛**；竖拍截图带 EXIF 方向，OCR 出的框坐标是歪的；长截图里的状态栏/输入框会污染文本块 |
| 没有"落盘与审计"的约定 | — | 演示时说不清"原始素材存哪、存了多久、有没有把真实手机号存进库里" |

一句话：**先让真实素材能进来，再谈模型。** 而且要把"为什么进来/为什么进不来/进来后动过什么"写成可审计的元数据。

## 2. 目标（做完之后，什么会不一样）

新增一层 `app/pipelines/media/`，**不改 `app/schemas/**`、不改 `app/api/**`**，对外只暴露两个函数：

```python
@dataclass
class PreparedAudio:
    sha256: str            # 原始字节哈希（原文件不入库，只存哈希）
    suffix: str            # 实际识别的容器：.wav / .m4a / .amr / unknown
    duration_s: float
    sample_rate: int       # 处理后的采样率（目标 16000）
    channels: int          # 处理后 1
    bit_depth: int
    segments: int          # 静音切段数（复用 T-02 的规则）
    peak: float            # 峰值（0–1，已归一）
    transcoded_by: str     # "native-wav" / "cli:<命令名>" / "not-supported"
    warnings: list[str]    # 例如 ["resampled 48000→16000", "clipped to 180s"]

def preprocess_audio(audio_bytes: bytes, suffix: str = ".wav") -> PreparedAudio: ...

@dataclass
class PreparedImage:
    sha256: str
    fmt: str               # png / jpeg / unknown
    width: int             # 应用 EXIF 方向之后的口径
    height: int
    rotate_deg: int        # 0 / 90 / 180 / 270（EXIF Orientation 换算）
    exif_present: bool
    needs_resize: bool     # 超过 4000px 长边或 4MB
    resize_target: tuple[int, int] | None
    crop_box: tuple[int, int, int, int] | None   # 去状态栏/输入框的坐标，不真裁
    mask_boxes: list[tuple[int, int, int, int]]  # 手机号/卡号/身份证的坐标，不真打码
    warnings: list[str]

def preprocess_image(image_bytes: bytes) -> PreparedImage: ...
```

**核心设计决择（必须写进 PR 说明，答辩会问）：**

1. **不装包**（`AGENTS.md` 硬约束第 1 条）。所以：
   - 音频：`wav` 走标准库 `wave`；**m4a/amr/mp3 靠外部 CLI 转码**，环境变量 `MEDIA_TRANSCODER`（形如 `ffmpeg -i {src} -ar 16000 -ac 1 {dst}`），没配就**明确拒绝并给转码指引**，不许假装成功。
   - 图片：像素级操作（真缩放/真打码）同样交给外部 CLI `MEDIA_IMAGER`；**没有 CLI 时本单交付的是"坐标 + 门槛判定"**，即 `rotate_deg`/`resize_target`/`crop_box`/`mask_boxes`，由前端按坐标显示或由外部工具执行。这既满足"预处理可审计"，又不违反不许装包。
2. **原文件不入库**：只落 `sha256` + 元数据；需要留证时落 `data/media_cache/<sha256>.<ext>`（`data/` 在 `.gitignore` 里），并写明保留策略（演示前清空）。
3. **上限要明说**：音频 >180s 截断并 `warnings` 标注；图片 >4MB 或长边 >4000px **不再直接拒**，而是给 `needs_resize` + `resize_target`，由上层决定"缩还是拒"。

## 4. 允许修改的路径（超出即越界）

```
app/pipelines/media/**        # 新目录，两个入口函数 + 私有实现
tests/media/**                # 单测，至少 8 条（见第 6 节）
data/samples/media/**         # 6 份真实素材，本地放着即可（data/ 不入库）
```

**不许碰**：`app/api/**`（接进 `/api/v1/detect/audio|image` 是队长的活）、`app/schemas/**`、`app/pipelines/audio/**`、`app/pipelines/vision/**`。
你要做的是"**喂给它们之前把素材洗干净**"，不是改它们。

## 5. 不许做的事（本次特有）

- 不许新增依赖（不许 `Pillow` / `numpy` / `librosa` / `ffmpeg-python` / `mutagen`）；外部 CLI 只经环境变量调用，不许写死路径。
- 不许伪造转码成功：没 CLI 就是 `transcoded_by="not-supported"` + 明确异常文案。
- 不许把原始音频/图片字节写进日志或异常信息（只记 `sha256` 前 12 位 + 尺寸）。
- 不许吞异常（`except: pass`）；解析失败一律抛具体异常（`UnsupportedAudioFormat` / `UnsupportedImageFormat` / `MediaTooLarge`）。
- 不许在预处理里做"判别"（打分、分级、剧本匹配是下游的事）。
