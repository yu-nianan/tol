# 任务单：三模态统一预处理 + 检测端口收口

## 1. 背景

文本、音频、图片三个入口现在各走各的：文本做了归一化和脱敏，音频图片还是空壳。将来 B 和 C 接上，
脱敏规则就会分成三份——改一处漏两处（上次"身份证被银行卡规则吃掉"就是这么来的）。

一句话：**把"进判别之前的那一段"收成一条通道。**

## 2. 要做什么（只讲方向）

1. **一条门**：三种输入都先经过同一个预处理，再进判别；以后加视频、加文件，也走这条门。
2. **一种形状**：不管输入是什么，出去的东西结构一致（文字内容、命中位置、把握大小、异常提醒），
   判别模块和前端都不需要知道"这是音频还是图片"。
3. **前端能看见**：结果里带上"是哪一句、哪个文字块、多大把握"，界面才能高亮到具体位置，
   而不是只给一个总分——这是本项目"可解释"的门面。
4. **缺东西要如实说**：没接 ASR/OCR 时，明确告诉调用方"这条通道还没接"，不许返回编造的文字。

## 3. 验收（怎么算做完）

- [ ] 三个入口都用上了同一个预处理，代码里只有一处做脱敏和归一化；
- [ ] 三个入口的返回字段完全一致——把三段返回并排贴在 PR 里就能看出来；
- [ ] 脱敏后的文本能还原回原句（报告和证据链要用）；
- [ ] 没接模型的通道，返回里写清"未接入"，而不是一个看不懂的报错；
- [ ] 前端只按一套结构写界面，不需要为音频、图片各写一套。

命令（队长会照着跑，必须全绿）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1 -Task all
python scripts/docs.py check
```

## 4. 边界

- **不动判别逻辑**：打分、阈值、分级一行不改，只改"进判别之前"和"出判别之后"的接口形状。
- **不许编造**：没有模型就说没有模型，这条比任何指标都硬。
- **需求主责转移**：`FR-1.4` 从 `T-00` 移到本单，所以本次**唯一允许**改 `T-00` 的地方是把它的 `covers` 摘掉 `FR-1.4`；改完跑一次 `python scripts/docs.py matrix` 一起提交。
- 前端怎么排版、用什么框架，不在本单范围内（那是 D 的单子）。

## 6. 交付时会问的三个问题

1. 为什么不让音频、图片各自直接进判别？（答：脱敏和异常判断会分成三份，改规则要改三处）
2. 加了这个之后，B、C 还要改什么？（答：只把自己识别出的文字和位置塞进来，前端不用改）
3. 没接模型的时候，演示怎么讲才不算吹牛？（答：说清"这条通道还没接"，并且界面能显示这句话）
