# 任务单：运行时库（薄单）

> 本单已交付，保留作边界说明与交接用；B 在它之上做 T-09 的画像/冷却/白名单。

## 1. 背景

- 对应需求：`FR-1.5`（多轮上下文不丢）、支撑 `FR-2.6`（个性化阈值需要历史）。
- 现状（做之前）：`engine.py` 的会话态是进程内 dict，重启即丢；告警也只活在内存里，刷新页面就查不到。

## 2. 目标

- 服务重启后，`GET /api/v1/report/{session_id}` 仍能出报告；`GET /api/v1/alerts/{id}` 仍能查到、仍能确认。
- `GET /api/v1/stats` 能给出会话/消息/告警/open 的真实计数（从库里数，不是从内存数）。

## 3. 输入 / 输出样例

```
# 第一轮
POST /api/v1/detect/text {"text":"我是公安局的…转到安全账户…","role":"elder","session_id":"s_demo"}
→ level=3 score=87.3 alert=A460bf7049a

# 重启服务后
GET /api/v1/report/s_demo → 200，score=92.6 turns=2（第二轮叠加后）
GET /api/v1/alerts/A460bf7049a → 200，status=open
```

## 8. 交付时会问的三个问题

1. 重启后数据还在吗？——在，`_hydrate()` 从 `sessions` 表回读。
2. 每次启动会不会把库清掉？——不会，只有 `RESET_DB=1` 才清。
3. 表结构以后要加字段怎么办？——升 `SCHEMA_VERSION`，在 `init_db()` 写迁移分支。
