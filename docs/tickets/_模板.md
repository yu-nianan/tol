# 任务单：<一句话说清要做什么>

> 用法：复制本文件 → 改名为 `T-<模块>-<短描述>.md` → 把下面每一项填满 → 发给负责人的那个智能体。
> **填不满就别开工**：任务单里没有"验收命令"的任务，一律视为没定义。

---

## 1. 背景（为什么做这件事）

- 对应需求：`FR-2.3`（多模态反诈 · 知识库检索）
- 对应测试用例：`TC-2.3`
- 一句话：让"安全账户"这类话术能检索到相似案例，并带回 case_id。

## 2. 目标（做完之后，什么会不一样）

- 例：`POST /api/v1/detect` 返回体的 `cited_case_ids` 不再为空，且至少 1 条来自 `app/kb/cases.jsonl`。

## 3. 输入 / 输出样例（写死，不要"大概"）

输入：

```json
{"user_id": "u_elder", "session_id": "s_1", "text": "把钱转到安全账户，这是资金审查"}
```

期望输出（关键字段）：

```json
{"score": 78.0, "level": "L2", "cited_case_ids": ["case_0031", "case_0107"]}
```

## 4. 允许修改的路径（超出即越界）

```
app/pipelines/knowledge/**
tests/knowledge/**
```

## 5. 不许做的事（本次特有）

- 不许改 `app/schemas/**`（缺字段先提申请）
- 不许新增依赖（要用向量库，用已批准的 FAISS）
- 不许在代码里硬编码 case_id 来"通过验收"

## 6. 验收命令（队长会照着跑，必须全绿）

```powershell
pwsh scripts/check.ps1 -Task lint
pwsh scripts/check.ps1 -Task test
pwsh scripts/check.ps1 -Task smoke
```

附加验收（人工看一眼）：

- [ ] 用 `data/samples/case_hit.txt` 里的文本调用接口，`cited_case_ids` 非空
- [ ] 检索耗时 < 300ms（记在 PR 里）

## 7. 预计与截止

| 项 | 内容 |
|---|---|
| 负责人（写进 front-matter 的 `owner`） | 队长 / A / B / C / D 里选一个 |
| 预计耗时 | 2 天（每天 ≤3 小时） |
| 截止 | 周日晚 22:00 |
| 卡住找谁 | @队长 |

> `owner` 只能填代号（见 `scripts/owners.txt`），不许填真名、不许填工具名、不许空着。
> 你写的每一份文档、每一份回执，`owner` 都从这张任务单抄。

## 8. 交付时会问的三个问题（提前想好）

1. 这个检索在扩到 1000 条案例时还够快吗？
2. 检索不到时，判别模块会怎么表现（会不会硬判 L3）？
3. 你的实现里，哪些是"演示用假数据"？
