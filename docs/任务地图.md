# A30 任务地图

> 这份文档只回答四个问题：**先做哪个、哪些能同时做、做完怎么交、怎么判断做完了**。
> 每个任务的细节在 `docs/tickets/`，需求原话在 [需求清单](需求清单.md)，覆盖关系看 [需求覆盖表](需求覆盖表.md)（自动生成）。

---

## 1. 一个任务能不能开工：只看三条线

| 线 | 就绪的标准 | 没就绪的后果 |
| --- | --- | --- |
| **契约** | `app/schemas/` 里的字段能装下它的输出 | 各写各的字段，联调时全推翻 |
| **数据** | `app/kb/` 或 `data/` 里有东西能喂 | 代码写完没东西跑，天天等素材 |
| **界面** | 前端有个位置能显示它 | 做完没人看见，演示时临时拼页面 |

三条线之外的东西（技术选型、依赖库、部署）都是"做完再说"，不构成开工前置。

## 4. 关键路径只有三条

1. `T-06 → T-07 → T-11 → 演示视频` —— 决定"能不能演示"；
2. `T-01 → T-08 → T-07` —— 决定"解释有没有证据"；
3. `T-04 → T-11` —— 决定"演示时看不看得见"。

这三条上的任务**只能由负责到底的人做**，不许试错、不许中途换人。其余任务（T-02、T-03、T-05、T-09、T-10、T-12）互相独立，谁空了谁上。

**并行度**：一周一批，每人手上只有 1 张任务单，全队同时推进 5 张。同时开 10 张的队，最后一张都交不出来。

## 5. 需求 ↔ 任务不是 1:1，用三个字段说清

任务单 front-matter 里：

```yaml
covers: [FR-2.2, FR-2.4a]      # 我主责，验收只看这几条
supports: [FR-2.6]             # 我只提供依赖，不负责验收
depends_on_task: [T-06]        # 必须先完成的任务单
```

四种真实情形：

| 情形 | 例子 | 怎么记 |
| --- | --- | --- |
| 一个任务抵几条需求 | T-07 一次覆盖 FR-2.2 / 2.4a / 2.7 | 全写进 `covers` |
| 一条需求要几个任务 | FR-1.4 同构证据＝T-00 定契约 + T-02/T-03 各自产出 | T-00 写 `covers`，T-02/T-03 写 `supports` |
| 一条需求前后端两段 | FR-3.3 监护人联动＝T-11 推送 + T-04 页面按钮 | 后端写 `covers`，前端写 `supports` |
| 一条需求分两期 | FR-2.3 检索：先 BM25（T-00），再混合（T-08） | 后做的那张写 `covers`，先做的写 `supports` |

**唯一硬规矩：一条需求只能有一张任务单把它写进 `covers`。** 写重了 `docs.py check` 直接红。
理由很实际：验收时只能找一个人，找两个人就等于没人负责。

## 7. 交接：三样东西，缺一不可

1. **冻结的接口**：函数签名 / schema 字段 / 错误码，写进 `docs/modules/<模块>.md`；
2. **回执**：`docs/reports/YYYY-MM-DD-<模块>-<人>.md`，重点是「下次接手要知道什么」；
3. **一条能跑的命令 + 一份样例数据**：接收方敲一遍就能看到结果。

**硬规矩：接收方 24 小时内必须跑通那条命令。跑不通当场打回，不许"先接着做"。**

交接时对方要能回答五问：接口在哪个文件？哪条路是死的？样例数据在哪？失败返回什么？下一层从哪个函数进？

## 8. 验收：三层，别混着用

| 层 | 用什么 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 机器 | `check.ps1 -Task all` + `docs.py check` | 没坏、没违规 | 做对了没有 |
| 功能 | 任务单 §7 验收用例表（输入 → 期望 → 需求 ID） | 这个功能按需求工作 | 整体能用 |
| 人 | 队长 3 分钟抽检（五个问题） | 真的能演示 | 代码好坏 |

**抽检五问**（不看代码）：

1. 现在能不能当场演示？点一下。
2. 反例跑过没有？结果给我看。
3. 它失败的时候返回什么？
4. 这个常数（阈值/权重）为什么是它？
5. 下一个人要加一个新剧本，从哪个函数进？

五问答不上三问，就是"文件提交了、任务没做完"。

---

## 9. 每周节奏（30 分钟，只做三件事）

1. 每人用三行汇报：做了什么 / 验收命令 / 结果；
2. 看 [需求覆盖表](需求覆盖表.md)：未认领的还有几条，谁下周领；
3. 只处理一件事：**卡住的那张单子**，当场决定"换路 / 砍功能 / 找人帮"。
