# A30 多模态反诈助手 · 技术学习路线

> 用途：会前预习。本文只回答两件事——**要学哪些技术、按什么顺序学**。
> 分工与"学到什么程度"留到下次会议定，本文不涉及。
>
> 项目一句话：把文本 / 音频 / 图片三种输入变成结构化证据 → 打分定级 → 弹窗预警、通知监护人 → 出一份报告。

---

## 一、技术全景（三层，21 项）

| 层 | 技术 | 谁基本都要会 |
|---|---|---|
| **底座** | Git、Python 环境（venv / 依赖 / 日志）、FastAPI、JSON 与 Pydantic、SQL、SQLite、Docker Compose | 是（后两项可按需） |
| **核心** | 结构化 Prompt、Function Calling、Embedding 与向量库、BM25 混合检索、ASR、VAD、OCR、pandas、正则与实体抽取 | 否，按模块领 |
| **交付** | React + Vite、WebSocket、ECharts、HTML→PDF、pytest、locust | 否，按模块领 |

一句话看懂依赖关系：

```
Git / Python 环境 ──► FastAPI ──► JSON(Pydantic) ──► SQLite
                          │
                          ├──► 结构化 Prompt ──► Function Calling
                          │            │
                          │            └──► Embedding / 向量库 ──► BM25 混合检索
                          │                                     │
                          │                                     └──► 规则打分（融合判别）
                          │
                          ├──► VAD ──► ASR        （音频一路）
                          └──► OCR                （图片一路）

交付侧：WebSocket ──► React 三屏 ──► ECharts ──► HTML→PDF 报告
质量侧：pytest ──► locust ──► Docker Compose
```

## 二、学习顺序（5 个阶段，含里程碑）

不绑周次。**同一阶段内的项可以同时学，跨阶段必须按顺序**——后一阶段离开前一阶段就学不动。

### 阶段 1 · 能跑起来（底座）

1. Git（仓库、提交、分支）
2. Python 环境（venv、requirements.txt、日志、.env）
3. FastAPI（路由、请求体、自动文档 `/docs`）
4. JSON 与 Pydantic（数据校验）
5. SQL 与 SQLite（建表、查询）

**为什么是这个顺序**：没有仓库和接口，后面所有代码都无处安放；数据库放最后，是因为前面几项跑通之后才有"东西"需要存。

**里程碑 M1**：一条命令起服务，浏览器打开 `/docs` 能看到 3 个接口，能写入并查出一条会话记录。

### 阶段 2 · 能判断（决策核心）

1. 结构化 Prompt（要求模型只输出 JSON）
2. JSON 校验与失败重试
3. Embedding 与向量库（先把案例变成向量存起来）
4. BM25 混合检索（关键词 + 语义两路合并）
5. 规则打分（把证据换算成 0–100 分与等级）

**为什么是这个顺序**：先让模型"从说人话变成说数据"，再谈检索（检索结果要能塞进 JSON 里当证据），最后才可能算分——打分器吃的是结构化证据，不是聊天记录原文。

**里程碑 M2**：给一段聊天记录，输出合法 JSON（诈骗类型 / 所处阶段 / 证据条目），并给出分数与等级。

### 阶段 3 · 能听能看（多模态输入）

1. VAD（把长音频切成有声音的片段）
2. ASR（语音转文字）
3. OCR（截图转文字 + 位置框）

**为什么是这个顺序**：不先切片就直接转写，长音频会超时甚至失败；OCR 与 ASR 互不依赖，可以两个人同时开工。

**里程碑 M3**：一段录音和一张截图，都能转成同一种 `Evidence` 结构，进同一个接口。

### 阶段 4 · 能演示（交互与产出）

1. WebSocket（后端推消息，前端实时弹窗）
2. React + Vite（三屏：检测页 / 告警页 / 报告页）
3. ECharts（风险分布、时间轴）
4. HTML → PDF（报告导出）
5. webhook 推送（企业微信 / 钉钉机器人）

**为什么是这个顺序**：先有推送通道，前端才有的可接；报告模板最后做，因为它只依赖数据、不依赖界面。

**里程碑 M4**：上传 → 弹窗告警 → 监护人收到消息 → 导出一份 PDF，端到端跑通一遍。

### 阶段 5 · 能交（质量与部署）

1. pytest（打分器、解析器的单元测试）
2. locust（并发压测，出时延图）
3. Docker Compose（app + 向量库一键起）

**里程碑 M5**：单测全绿、压测有图、一条命令起全栈，并能写出部署文档。

## 五、明确不学（两个月内投入产出比太低）

- 模型训练 / 微调 / 部署自有大模型（用 API 就够）
- Kubernetes、微服务治理、消息队列
- React 底层原理（diff 算法、hooks 源码）、Webpack / Vite 配置细节
- 声学模型、检测网络（ASR 与 OCR 会调、会看输出、会处理失败就够）
- 图数据库（本项目用关系表 + 向量库即可）

---

## 六、学习方式（四条，比学什么更重要）

1. **抄官方 quickstart，先跑通再改**。不要从"教程第一章"开始系统学，直接拿能跑的示例改参数。
2. **一次只跑通一个最小示例**：学 ASR 就只做"一段录音出文字"，别顺手搭界面。
3. **卡住超过 2 小时就在群里说**，不许自己硬扛——这是练习期最常见的进度杀手。
4. **每学完一项，留 10 行笔记 + 一个能复用的代码片段**，放进仓库 `docs/notes/`。两个月后你会感谢自己。
