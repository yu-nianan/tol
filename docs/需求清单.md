# A30 多模态反诈助手 · 需求清单

> 依据：《第十七届中国大学生服务外包创新创业大赛 A 类赛题手册》A30 题面（第 164–171 页）。
> 本文把题面的"背景 / 用户期望 / 任务要求 / 指标 / 提交材料"整理成可执行、可验收的需求条目，作为需求基线。
> 编号规则：`FR-模块.序号` 功能需求，`NFR-序号` 非功能需求，`D-序号` 交付物。优先级用 MoSCoW（M 必须 / S 应该 / C 可以）。

---

## 一、项目定位

一个具备 **感知 – 决策 – 干预 – 进化** 能力的多模态反诈智能体：接收文本、音频、视觉输入，抽取结构化证据，检索反诈知识库，融合打分定级，按等级弹窗 / 语音提醒 / 联动监护人，并沉淀新案例、自动扩充知识库。

一句话验收：**演示视频里能完整看到"诱导 → 识别 → 预警 → 监护人通知"这条链路走通。**

### 1.1 一句话主张

> 一般的安全软件只在你点下转账那一刻才拦你；我们在你被说服之前就提醒你，并且说得清凭什么、叫得动你信得过的人。

对外（PPT、视频旁白）统一用这一句；内部统一理解为 **早（阶段预警）/ 准（跨模态矛盾证据）/ 接住（家庭协同）** 一件事，不是三件事。

### 1.2 三条创新轴与需求锚点

| 创新轴 | 主张 | 需求锚点 | 自证指标 | 材料体现 |
|---|---|---|---|---|
| A 时点 | 不等转账，在"被说服"阶段就预警 | FR-2.2 阶段预警口径 | 黑样本 ≥90% 预警轮次早于转账意图轮次 | 演示视频主线 + 对比曲线 |
| B 依据 | 跨模态矛盾作证据（合成音 / 截图与银行模板不符 / 号码与自称身份冲突） | FR-2.4b、FR-2.8 证据链 | 伪造集 precision ≥0.8、recall ≥0.7；消融证明去掉后误报上升 | 告警页证据条目 + 消融表 |
| C 对象 | 不只提醒本人，把"他信的人"拉进来 | FR-3.3、FR-2.6 | 分级告警三档可见差异 + 监护人确认回写 | 告警流程图 + 真实角色切换演示 |

三条必须是一条链：早发现 → 说清依据 → 有人兜住。立项材料里不要拆成三个并列亮点。

### 1.3 证明层（评测，不单独算创新）

- 主集 100 条，黑白 1:1，黑样本覆盖 ≥10 类剧本；指标报准确率 + 精确率/召回率 + F1。
- **变异集 ≥30 条**（同义改写、错别字、语调变化、方言片段），识别率相对主集下降 ≤10%（NFR-11）。
- **伪造集**：20 张 PS 截图 + 10 段合成语音，专测跨模态矛盾（FR-2.4b）。
- 所有指标写清 n 与置信区间；必附单模态 vs 三模态消融表。
- 不报"业界第一""国际领先"这类无法自证的结论。

### 1.4 边界（防止越写越虚）

- 不加"第四条创新"；任何新想法先进 Issue，不直接进本文。
- 知识库自动更新（FR-4）只做到"有入口 + 能入库"，不当创新点写。
- "大模型 + 多模态"是技术手段，不是创新点；评审追问时回答"手段是现成的，缝在时点、依据、对象"。

## 二、需求来源（题面痛点 → 需求映射）

| 题面指出的问题 | 转成的需求 |
|---|---|
| 响应滞后，依赖用户举报 | FR-2.4a 自动判别 + FR-3.1 分级预警（在转账前就提醒，见创新轴 A） |
| 跨平台、跨渠道有盲区 | FR-1.1–1.3 三模态全渠道接入 |
| 缺乏个性化防护 | FR-2.6 个性化阈值 + FR-3.6 分角色建议 + FR-3.7 角色设置 |
| 只靠单一模态 | FR-2.4a 多模态融合判别 + FR-2.4b 跨模态矛盾检测（创新轴 B） |
| （新增）预警时点靠转账才触发 | FR-2.2 阶段预警口径（创新轴 A） |
| （新增）只提醒本人、家人不知情 | FR-3.3 + FR-2.6 家庭协同与角色阈值偏移（创新轴 C） |
| 无法自主学习新手法 | FR-4.1–4.3 案例入库与生效验证 |
| 监护人无法及时介入 | FR-3.3 监护人联动（通报 + 确认回写 + 远程干预入口） |

目标人群与典型手法（来自题面，用于测评集选样）：老年人—养生保健 / 冒充子女；儿童青少年—游戏交易 / 追星诱导；中青年—投资理财 / 兼职刷单 / 虚假贷款。

## 三、功能需求

### FR-1 多模态输入

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-1.1 | 文本接入：聊天记录、短信，支持粘贴与文件上传 | M | 演示两种入口各跑一次 |
| FR-1.2 | 音频接入：语音文件（通话录音 / 语音消息） | M | 一段 30s 录音转出文字并进入判别 |
| FR-1.3 | 视觉接入：屏幕截图、图片；视频流至少支持抽帧 | M | 聊天截图与转账页各识别一次 |
| FR-1.4 | 三模态统一预处理，输出同构的 `Evidence` 结构 | M | 三种输入的证据字段一致，可进同一接口 |
| FR-1.5 | 会话与多轮上下文：对话历史存储与检索，保证多轮一致 | M | 同一会话连续 5 轮，上下文不丢 |

### FR-2 智能识别与决策

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-2.1 | 意图识别：Prompt 判定"是否诈骗 / 属哪一类"，输出结构化 JSON | M | 测评集上分类准确率 |
| FR-2.2 | 阶段判定：识别对话处于剧本哪一阶段（接触 / 立威 / 隔离 / 诱导转账），并**在转账意图出现之前**给出预警 | S | 黑样本 ≥90% 满足"预警轮次 < 转账意图轮次"；附关键词法 vs 阶段法两条对比曲线 |
| FR-2.3 | 知识库检索：向量库存法规与典型案例，按上下文检索相似案例并作为证据引用 | M | 检索结果带 case_id，解释中可引用 |
| FR-2.4a | 多模态融合判别：融合多源证据给出 0–100 分与风险等级 | M | 消融表：单模态 vs 三模态 |
| FR-2.4b | **跨模态矛盾检测**：识别三类矛盾并作为证据——①语音合成痕迹（机械感/无呼吸声/音画不同步）②截图版面与银行/平台官方模板偏离 ③来电号码归属地与自称身份冲突 | S | 自建伪造集上 precision ≥0.8、recall ≥0.7；消融：去掉矛盾项后误报上升（见 1.3） |
| FR-2.5 | 剧本覆盖：不少于 10 种典型诈骗剧本（重点含 AI 合成语音、投资理财、兼职刷单、虚假征信） | M | 剧本库清单 + 每类 ≥3 条案例 |
| FR-2.6 | 个性化风险评估：结合角色属性（老人 / 儿童 / 青壮年 / 财会等）与长短期记忆动态调整阈值 | M | 同一案例换角色，等级/阈值发生变化 |
| FR-2.7 | 幻觉抑制：无检索证据时不得给出最高等级（置信度封顶） | S | 构造"无相似案例"输入，等级不越级 |
| FR-2.8 | 可解释：每条告警都能给出证据链与一段人话解释 | M | 告警详情页可见证据条目 |

### FR-3 实时干预与交互

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-3.1 | 分级预警：至少三级（提示 / 警告 / 紧急），强度递增 | M | 三级各演示一次 |
| FR-3.2 | 语音提醒：警告及以上触发语音播报 | M | 演示中听到播报 |
| FR-3.3 | 监护人联动：可配置监护人；紧急级自动推送；支持确认回写与远程干预入口；告警等级随角色（老人 / 儿童 / 普通）偏移 | M | 同一输入切换角色，等级可见差异；企业微信/钉钉收到消息并点"已介入" |
| FR-3.4 | 报告生成：自动生成可视化《安全监测报告》（风险说明 + 防御建议），可导出 | M | 导出一份 PDF，内容五段齐全 |
| FR-3.5 | 周期总结：按周/月向监护人推送安全状况摘要 | C | 有入口即可，不要求演示 |
| FR-3.6 | 个性化防护建议：按角色给差异化提醒与教育内容 | S | 老人与学生的建议文案不同 |
| FR-3.7 | 角色设置：用户可设置角色类型（老人 / 儿童 / 青壮年 / 性别 / 职业） | M | 设置页可改并影响判定 |

### FR-4 自适应进化

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-4.1 | 新案例入库流水线：清洗 → 结构化 → 去重 → 向量化 → 写库并打版本号 | M | 导入一条新案例，流水线跑通 |
| FR-4.2 | 人工审核开关：新案例默认待审，审核后才可被检索 | S | 审核前检索不到、审核后能检索到 |
| FR-4.3 | 生效验证：入库后相似查询能命中新案例 | M | 演示"入库前查不到 / 入库后查得到" |

### FR-5 工程与交付

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-5.1 | 可运行程序 + 部署文档（一键起） | M | `docker compose up` 后能访问 |
| FR-5.2 | 自建测评集：≥20 案例，黑白 1:1，黑样本覆盖 ≥10 类，含文本 / 音频 / 图片（或视频） | M | 提交测评集文件与说明 |
| FR-5.3 | 评估报告：F1-score、准确率、响应时延、压测结果 | M | 报告含四类数据与图表 |
| FR-5.4 | 使用指南：安装、配置、操作步骤 | M | 一份文档，外人照着能跑 |
| FR-5.5 | 演示视频：完整展示"诱导 → 识别 → 预警 → 监护人通知" | M | 视频成片 |

## 四、非功能需求

| 编号 | 需求 | 目标值 | 测量方法 |
|---|---|---|---|
| NFR-1 | 响应时延 | 文本 / 图片 P95 < 10s（内部目标 5s）；音频 ≤30s 同步、>60s 异步 | 打点日志 + 压测脚本统计 P50/P95 |
| NFR-2 | 并发能力 | ≥10 并发稳定（内部目标 20） | locust 压测 10 分钟，成功率 ≥99% |
| NFR-3 | 稳定性 | 连续运行 24h 无崩溃 | 守护进程记录 + 内存曲线 |
| NFR-4 | 融合识别准确率 | > 90%（内部目标 92%） | 100 条自建测评集，3 次投票取多数 |
| NFR-5 | 误报率 | 正常社交行为 < 5% | 100 条"含敏感词的正常对话"，FP/(FP+TN) |
| NFR-6 | 隐私 | 手机号、身份证、银行卡脱敏存储；日志不落原文 | 抽查数据库与日志 |
| NFR-7 | 安全 | 接口鉴权（token）、上传类型与大小限制、密钥走环境变量 | 代码审查 + 越权测试 |
| NFR-8 | 可维护 | 模块边界清晰、接口契约稳定、关键路径有日志 | 代码结构评审 |
| NFR-9 | 可移植 | Docker Compose 一键起（app + 向量库） | 换一台机器复现 |
| NFR-10 | 合规 | 只做"提醒与引导"，不做系统级拦截；界面有免责声明 | 方案与界面自查 |
| NFR-11 | 变异鲁棒性 | 同一诈骗意图的同义改写 / 错别字 / 变调 ≥30 条，识别率相对主集下降 ≤10% | 变异集跑分表（见 1.3） |

## 五、硬指标与口径（题面原文 → 我们的口径）

| 题面原文 | 我们的口径 | 注意 |
|---|---|---|
| 多模态融合识别场景下准确率 > 90% | 100 条测评集（黑 50 / 白 50），三模态输入子集单独统计 | 必须附**消融表**（单模态 vs 融合），否则这条指标没有落脚点 |
| 正常社交行为误报率 < 5% | 100 条含"钱/转账/验证码/银行卡"的正常对话 | 用纯寒暄样本算误报率是自欺欺人 |
| 精准识别不少于 10 种典型诈骗剧本 | 剧本库 10 类，每类 ≥3 条真实案例 | 剧本要按"阶段"建模，不是关键词表 |
| 文本 / 图片响应 < 10 秒 | P95 < 10s，LLM 超时 6s 降级规则兜底 | 必须有降级路径，否则网络抖动就破指标 |
| 连续运行测试无崩溃 | 24h 连续跑批 + 内存监控 | 需要留出专门时间跑 |
| 三模态联合分析 | 同一会话可同时送文本 + 音频 + 截图 | 演示时用"通话录音 + 聊天截图"组合最有说服力 |
| 诱导－预警－监护人联动全链路闭环 | 端到端脚本可复现 | 演示视频的主线就是这条 |
| （新增）预警时点 | 黑样本 ≥90% 满足"预警轮次 < 转账意图轮次" | 对应创新轴 A；附关键词法 vs 阶段法两条曲线 |
| （新增）跨模态矛盾检测 | 伪造集 precision ≥0.8、recall ≥0.7，且消融去掉后误报上升 | 对应创新轴 B；样本来自自建伪造集（20 张 PS 截图 + 10 段合成音） |

**统计提醒**：20 条样本（19 对 = 95%）的 95% 置信区间约为 **[76%, 99%]**，撑不起"大于 90%"的结论。建议官方交 20 条、内部评 100 条，报告里写明样本量与置信区间。

## 七、范围边界（明确不做，防止项目失控）

- 不做系统级来电拦截、不替用户挂断电话（改为提醒 + 引导 + 一键求助）
- 不接运营商、银行、公安的真实接口（用模拟黑名单 / 模拟回执）
- 不训练、不微调自有大模型（走 API）
- 不做运营后台、多租户、计费
- 不追求覆盖全部诈骗类型（聚焦 10 类）
- 不做移动原生 App（Web 优先，必要时做 H5）

## 十、风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 官方数据未拿到 | 案例库与测评集无从构建 | 先用公开警情通报 + 新闻案例顶上，拿到再替换 |
